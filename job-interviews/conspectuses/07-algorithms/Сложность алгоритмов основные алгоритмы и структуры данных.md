Практический конспект для Lead/Senior PHP backend developer перед интервью. Цель: быстро объяснять сложность, выбирать структуры данных, узнавать типовые паттерны задач и понимать, когда достаточно встроенных возможностей PHP.

## Как пользоваться

- Сначала повторить Big O, структуры данных и PHP-специфику.
- Затем пройти паттерны задач: binary search, two pointers, sliding window, BFS/DFS, DP, greedy.
- Для интервью тренировать короткое объяснение: что делаем, почему корректно, какая сложность, какие крайние случаи.
- В реальном backend-коде помнить: правильная структура данных часто важнее микрооптимизаций.

## Big O, Theta и Omega

`Big O` описывает верхнюю асимптотическую границу роста времени или памяти при увеличении входа `n`.

- `O(1)` - константное время: доступ к элементу массива по индексу в обычном массиве на уровне абстрактной модели.
- `O(log n)` - логарифмическое: бинарный поиск, операции в сбалансированном дереве.
- `O(n)` - линейное: один проход по коллекции.
- `O(n log n)` - типичная эффективная сортировка сравнением.
- `O(n^2)` - вложенные проходы по всем парам.
- `O(2^n)`, `O(n!)` - перебор подмножеств или перестановок.

`Theta`, `Theta(f(n))`, означает точную асимптотическую оценку сверху и снизу: алгоритм растет как `f(n)`.

`Omega`, `Omega(f(n))`, означает нижнюю границу: алгоритм не может работать быстрее `f(n)` в заданной модели или конкретном случае.

На интервью обычно достаточно сказать:

> В худшем случае `O(n)`, в среднем `Theta(n)`, дополнительная память `O(1)`.

## Время против памяти

Временная сложность отвечает на вопрос, как растет число операций. Пространственная сложность отвечает, сколько дополнительной памяти нужно сверх входных данных.

Примеры компромисса:

- Поиск дублей вложенными циклами: `O(n^2)` времени, `O(1)` памяти.
- Поиск дублей через `set`: `O(n)` ожидаемого времени, `O(n)` памяти.
- Prefix sums: запрос суммы отрезка за `O(1)`, но нужна память `O(n)`.
- Кеширование/мемоизация: меньше времени, больше памяти.

Для backend-разработчика важно учитывать не только Big O, но и реальные константы: размер payload, сетевые вызовы, SQL-запросы, сериализация, копирование массивов PHP.

## Амортизированная сложность

Амортизированная сложность оценивает среднюю стоимость операции в последовательности операций, даже если отдельная операция иногда дорогая.

Примеры:

- Динамический массив иногда расширяется и копирует элементы, но `append` амортизированно `O(1)`.
- Hash table иногда делает rehash, но вставка/поиск ожидаемо `O(1)`.
- Очередь на двух стеках: отдельный перенос `O(n)`, но каждая операция амортизированно `O(1)`.

Короткий ответ:

> Амортизированное `O(1)` означает, что дорогие операции редки, и если распределить их стоимость на длинную серию операций, средняя стоимость одной операции константная.

## Рекурсия и стек

Рекурсия использует call stack. Глубина рекурсии влияет на память: если глубина `h`, стек занимает `O(h)`.

Примеры:

- DFS в дереве высоты `h`: время `O(n)`, стек `O(h)`.
- DFS в вырожденном дереве: стек `O(n)`.
- Бинарный поиск рекурсивно: стек `O(log n)`, итеративно `O(1)`.

В PHP нет практичной tail-call optimization. Глубокую рекурсию лучше заменять итеративным алгоритмом со `SplStack` или обычным массивом как стеком.

```php
<?php

function factorial(int $n): int
{
    if ($n < 2) {
        return 1;
    }

    return $n * factorial($n - 1);
}
```

Для больших `n` этот пример плох: риск переполнения стека и переполнения `int`.

## Структуры данных

### Массивы и списки

В классической модели массив дает доступ по индексу `O(1)`, вставку в конец амортизированно `O(1)`, вставку в начало/середину `O(n)`.

В PHP `array` - не компактный C-style array, а ordered hash map. Он хранит порядок вставки, поддерживает integer/string ключи и имеет заметный overhead памяти.

```php
<?php

$items = [10, 20, 30];
$items[] = 40;       // ожидаемо O(1) амортизированно
array_unshift($items, 5); // O(n), переиндексация
```

Когда важна память и фиксированный размер, можно рассмотреть `SplFixedArray`, но API менее удобный, а выигрыш зависит от сценария.

```php
<?php

$arr = new SplFixedArray(3);
$arr[0] = 'a';
$arr[1] = 'b';
$arr[2] = 'c';
```

### Связные списки

Связный список дает вставку/удаление известного узла за `O(1)`, но поиск и доступ по индексу `O(n)`. В PHP редко нужен в прикладном backend-коде: overhead объектов обычно велик.

`SplDoublyLinkedList` может использоваться как deque, stack или queue, но чаще проще `SplQueue`/`SplStack`.

### Hash tables и maps

Hash table хранит пары ключ-значение. Ожидаемо:

- lookup: `O(1)`;
- insert: `O(1)`;
- delete: `O(1)`;
- worst-case теоретически `O(n)` при плохих коллизиях.

В PHP обычный `array` часто используется как map:

```php
<?php

$byId = [];
$byId[42] = ['id' => 42, 'name' => 'Ada'];

if (isset($byId[42])) {
    // Быстрая проверка наличия непустого значения.
}
```

Важно: `isset($map[$key])` вернет `false`, если значение `null`. Для точной проверки ключа используйте `array_key_exists($key, $map)`.

### Sets

В PHP нет отдельного встроенного `Set`. Обычно используют associative array со значением `true`.

```php
<?php

$seen = [];

foreach ($ids as $id) {
    if (isset($seen[$id])) {
        return true;
    }

    $seen[$id] = true;
}

return false;
```

Сложность: ожидаемо `O(n)` времени и `O(n)` памяти.

### Stack

Stack работает по принципу LIFO: last in, first out.

Операции `push`/`pop` ожидаемо `O(1)`.

```php
<?php

$stack = new SplStack();
$stack->push('first');
$stack->push('second');

echo $stack->pop(); // second
```

Можно использовать обычный массив с `$stack[] = $x` и `array_pop($stack)`. Не используйте `array_shift` для стека: это `O(n)`.

### Queue

Queue работает по принципу FIFO: first in, first out.

```php
<?php

$queue = new SplQueue();
$queue->enqueue('job-1');
$queue->enqueue('job-2');

echo $queue->dequeue(); // job-1
```

`array_shift($array)` в PHP дорогой для больших массивов, потому что переиндексирует элементы. Для очередей используйте `SplQueue` или храните индекс начала.

### Deque

Deque поддерживает добавление и удаление с обоих концов. Полезен для sliding window maximum, BFS, LRU-подобных задач.

В PHP можно использовать `SplDoublyLinkedList`, но для интервью часто достаточно описать абстрактную структуру.

### Heap и Priority Queue

Heap позволяет быстро получать минимум или максимум.

- `insert`: `O(log n)`;
- `extractMin`/`extractMax`: `O(log n)`;
- `peek`: `O(1)`.

В PHP есть `SplPriorityQueue`, по умолчанию это max-priority queue.

```php
<?php

$pq = new SplPriorityQueue();
$pq->insert('low', 1);
$pq->insert('high', 10);

echo $pq->extract(); // high
```

Для Dijkstra с минимальными расстояниями можно хранить отрицательный priority: `-$distance`.

Особенность `SplPriorityQueue`: при одинаковых приоритетах порядок не гарантирован. Также при извлечении можно настроить режим через `setExtractFlags`.

### Trees

Дерево - иерархическая структура без циклов.

Типовые варианты:

- Binary tree: у узла до двух детей.
- Binary search tree: слева меньше, справа больше.
- Balanced tree: высота `O(log n)`.
- B-tree/B+tree: важны для индексов БД.

Операции в сбалансированном BST: search/insert/delete `O(log n)`. В вырожденном дереве: `O(n)`.

Обходы:

- preorder: node, left, right;
- inorder: left, node, right;
- postorder: left, right, node;
- level-order: BFS по уровням.

### Tries

Trie, или prefix tree, хранит строки по символам/токенам.

Операции поиска/вставки: `O(L)`, где `L` - длина строки, не количество всех строк.

Использования:

- autocomplete;
- prefix search;
- словари;
- маршрутизация по сегментам, если нужно искать префиксы.

Минус: память может быть большой.

### Graphs

Граф состоит из вершин и ребер. Бывает directed/undirected, weighted/unweighted, cyclic/acyclic.

Представления:

- adjacency list: память `O(V + E)`, хорошо для разреженных графов;
- adjacency matrix: память `O(V^2)`, быстрая проверка ребра `O(1)`, плохо для больших разреженных графов.

В PHP adjacency list удобно хранить массивом:

```php
<?php

$graph = [
    'A' => ['B', 'C'],
    'B' => ['D'],
    'C' => [],
    'D' => [],
];
```

## Sorting

### Основные алгоритмы сортировки

| Алгоритм | Время среднее | Время худшее | Память | Стабильность | Когда знать |
|---|---:|---:|---:|---|---|
| Bubble sort | `O(n^2)` | `O(n^2)` | `O(1)` | да | учебный пример, почти не использовать |
| Insertion sort | `O(n^2)` | `O(n^2)` | `O(1)` | да | малые или почти отсортированные массивы |
| Selection sort | `O(n^2)` | `O(n^2)` | `O(1)` | нет | редко, минимум записей |
| Merge sort | `O(n log n)` | `O(n log n)` | `O(n)` | да | стабильность, linked lists, external sort |
| Quick sort | `O(n log n)` | `O(n^2)` | `O(log n)` стек | нет | быстрый на практике при хорошем pivot |
| Heap sort | `O(n log n)` | `O(n log n)` | `O(1)` | нет | когда нужна гарантия по памяти |
| Counting sort | `O(n + k)` | `O(n + k)` | `O(k)` | да | целые ключи в малом диапазоне |
| Radix sort | `O(d(n + k))` | `O(d(n + k))` | `O(n + k)` | да | строки/числа фиксированной длины |

Нижняя граница для сортировок сравнением: `Omega(n log n)`.

### Когда использовать встроенную сортировку PHP

В production почти всегда используйте встроенные функции `sort`, `rsort`, `asort`, `ksort`, `usort`, `array_multisort`, если нет специальной причины писать свою сортировку.

Причины:

- встроенная реализация оптимизирована и протестирована;
- код проще читать и сопровождать;
- ошибки в comparator часто дороже гипотетической выгоды.

```php
<?php

usort($users, static fn (array $a, array $b): int => $a['age'] <=> $b['age']);
```

На интервью важно сказать:

> В реальном PHP-коде я предпочту встроенную сортировку и сфокусируюсь на корректном comparator, стабильности, сохранении ключей и размере входа. Свой алгоритм пишу только если задача учебная или нужна специальная сортировка вроде counting/radix для ограниченного домена.

## Binary Search

Бинарный поиск работает на отсортированном монотонном пространстве. Сложность `O(log n)` времени и `O(1)` памяти в итеративной версии.

```php
<?php

function binarySearch(array $nums, int $target): int
{
    $left = 0;
    $right = count($nums) - 1;

    while ($left <= $right) {
        $mid = intdiv($left + $right, 2);

        if ($nums[$mid] === $target) {
            return $mid;
        }

        if ($nums[$mid] < $target) {
            $left = $mid + 1;
        } else {
            $right = $mid - 1;
        }
    }

    return -1;
}
```

Pitfall: в языках с integer overflow лучше писать `$mid = $left + intdiv($right - $left, 2)`. В PHP на 64-bit это реже проблема, но привычка хорошая.

Binary search часто применяется не только по массиву, но и по ответу: минимальная скорость, минимальный capacity, первая версия с ошибкой.

## Two Pointers

Два указателя подходят для отсортированных массивов, палиндромов, удаления дублей, поиска пары с суммой.

```php
<?php

function hasPairWithSum(array $nums, int $target): bool
{
    $left = 0;
    $right = count($nums) - 1;

    while ($left < $right) {
        $sum = $nums[$left] + $nums[$right];

        if ($sum === $target) {
            return true;
        }

        if ($sum < $target) {
            $left++;
        } else {
            $right--;
        }
    }

    return false;
}
```

Сложность: `O(n)` времени, `O(1)` памяти, если массив уже отсортирован.

## Sliding Window

Sliding window применим для подстрок/подмассивов с непрерывным диапазоном.

Пример: максимальная сумма подмассива длины `k`.

```php
<?php

function maxSumWindow(array $nums, int $k): int
{
    $n = count($nums);

    if ($k <= 0 || $k > $n) {
        throw new InvalidArgumentException('Invalid window size');
    }

    $sum = array_sum(array_slice($nums, 0, $k));
    $best = $sum;

    for ($i = $k; $i < $n; $i++) {
        $sum += $nums[$i] - $nums[$i - $k];
        $best = max($best, $sum);
    }

    return $best;
}
```

Сложность: `O(n)` времени. Важно не пересчитывать окно с нуля, иначе будет `O(nk)`.

## Prefix Sums

Prefix sums позволяют быстро считать сумму диапазона.

```php
<?php

function buildPrefixSums(array $nums): array
{
    $prefix = [0];

    foreach ($nums as $num) {
        $prefix[] = $prefix[count($prefix) - 1] + $num;
    }

    return $prefix;
}

function rangeSum(array $prefix, int $left, int $right): int
{
    return $prefix[$right + 1] - $prefix[$left];
}
```

Построение `O(n)`, запрос `O(1)`, память `O(n)`.

## BFS и DFS

### BFS

BFS обходит граф по слоям. Используется для кратчайшего пути в unweighted graph, level-order traversal, поиска минимального числа шагов.

Сложность: `O(V + E)` времени, `O(V)` памяти.

```php
<?php

function bfs(array $graph, string $start): array
{
    $visited = [$start => true];
    $order = [];
    $queue = new SplQueue();
    $queue->enqueue($start);

    while (!$queue->isEmpty()) {
        $node = $queue->dequeue();
        $order[] = $node;

        foreach ($graph[$node] ?? [] as $next) {
            if (!isset($visited[$next])) {
                $visited[$next] = true;
                $queue->enqueue($next);
            }
        }
    }

    return $order;
}
```

### DFS

DFS идет в глубину. Используется для connected components, cycle detection, topological sort, backtracking.

```php
<?php

function dfs(array $graph, string $start): array
{
    $visited = [];
    $order = [];
    $stack = new SplStack();
    $stack->push($start);

    while (!$stack->isEmpty()) {
        $node = $stack->pop();

        if (isset($visited[$node])) {
            continue;
        }

        $visited[$node] = true;
        $order[] = $node;

        foreach (array_reverse($graph[$node] ?? []) as $next) {
            if (!isset($visited[$next])) {
                $stack->push($next);
            }
        }
    }

    return $order;
}
```

## Dijkstra Basics

Dijkstra ищет кратчайшие пути от одной вершины до остальных в графе с неотрицательными весами.

Сложность с priority queue: `O((V + E) log V)`.

Нельзя использовать с отрицательными ребрами. Для них нужны Bellman-Ford или другие алгоритмы.

```php
<?php

function dijkstra(array $graph, string $source): array
{
    $dist = [$source => 0];
    $pq = new SplPriorityQueue();
    $pq->setExtractFlags(SplPriorityQueue::EXTR_BOTH);
    $pq->insert($source, 0);

    while (!$pq->isEmpty()) {
        $current = $pq->extract();
        $node = $current['data'];
        $distance = -$current['priority'];

        if ($distance > ($dist[$node] ?? PHP_INT_MAX)) {
            continue;
        }

        foreach ($graph[$node] ?? [] as $edge) {
            [$next, $weight] = $edge;
            $newDistance = $distance + $weight;

            if ($newDistance < ($dist[$next] ?? PHP_INT_MAX)) {
                $dist[$next] = $newDistance;
                $pq->insert($next, -$newDistance);
            }
        }
    }

    return $dist;
}
```

Формат графа:

```php
<?php

$graph = [
    'A' => [['B', 5], ['C', 1]],
    'C' => [['B', 2]],
    'B' => [],
];
```

## Topological Sort

Topological sort упорядочивает вершины DAG так, что каждое ребро `u -> v` идет от более ранней вершины к более поздней.

Использования:

- порядок выполнения задач;
- dependency resolution;
- миграции;
- build pipelines.

Kahn algorithm:

```php
<?php

function topologicalSort(array $graph): array
{
    $indegree = [];

    foreach ($graph as $node => $neighbors) {
        $indegree[$node] ??= 0;

        foreach ($neighbors as $next) {
            $indegree[$next] = ($indegree[$next] ?? 0) + 1;
        }
    }

    $queue = new SplQueue();

    foreach ($indegree as $node => $degree) {
        if ($degree === 0) {
            $queue->enqueue($node);
        }
    }

    $order = [];

    while (!$queue->isEmpty()) {
        $node = $queue->dequeue();
        $order[] = $node;

        foreach ($graph[$node] ?? [] as $next) {
            $indegree[$next]--;

            if ($indegree[$next] === 0) {
                $queue->enqueue($next);
            }
        }
    }

    if (count($order) !== count($indegree)) {
        throw new RuntimeException('Graph has a cycle');
    }

    return $order;
}
```

Сложность: `O(V + E)`.

## Dynamic Programming Basics

Dynamic programming применяется, когда есть overlapping subproblems и optimal substructure.

Подход:

- определить состояние `dp[...]`;
- определить переход;
- определить базовые случаи;
- выбрать порядок вычислений;
- оценить время и память.

Пример: количество способов подняться на `n` ступенек, если можно идти на 1 или 2.

```php
<?php

function climbStairs(int $n): int
{
    if ($n <= 2) {
        return max(1, $n);
    }

    $prev2 = 1;
    $prev1 = 2;

    for ($i = 3; $i <= $n; $i++) {
        $current = $prev1 + $prev2;
        $prev2 = $prev1;
        $prev1 = $current;
    }

    return $prev1;
}
```

Сложность: `O(n)` времени, `O(1)` памяти.

Короткий senior-level ответ:

> Я сначала формулирую состояние и инвариант. Если рекурсивное решение пересчитывает одни и те же состояния, добавляю memoization. Если порядок зависимостей понятен, перевожу в bottom-up и по возможности сжимаю память.

## Greedy Algorithms

Greedy делает локально лучший выбор и не пересматривает его. Работает не всегда: нужна доказуемая корректность, например exchange argument или matroid-like структура.

Примеры, где greedy обычно работает:

- interval scheduling по раннему окончанию;
- Huffman coding;
- minimum spanning tree: Kruskal/Prim;
- Dijkstra при неотрицательных весах.

Примеры, где простой greedy может не работать:

- coin change с произвольными номиналами;
- knapsack 0/1;
- многие задачи планирования с дополнительными ограничениями.

На интервью:

> Greedy недостаточно предложить интуитивно. Нужно объяснить, почему локальный выбор не ухудшает оптимальное решение, или привести контрпример и перейти к DP.

## PHP-специфика

### PHP arrays

PHP `array` - ordered hash map, а не компактный массив.

Практические следствия:

- удобно использовать как list, map и set;
- память существенно выше, чем у packed arrays в низкоуровневых языках;
- integer keys и string keys ведут себя по-разному, numeric strings могут приводиться к int;
- `array_values` копирует и переиндексирует;
- `array_merge` и spread могут копировать большие массивы;
- `foreach` обычно предпочтительнее ручной индексации для map-like arrays.

### SplFixedArray

`SplFixedArray` фиксированного размера, может быть экономнее по памяти для больших плотных массивов, но менее удобен и не всегда быстрее.

Используйте только после измерений или когда задача явно требует фиксированного indexed storage.

### SplStack, SplQueue, SplPriorityQueue

Используйте SPL-структуры для явных стеков, очередей и priority queues. Это повышает ясность намерения и избегает `array_shift` на больших данных.

### Generators

Generators позволяют лениво производить значения и экономить память.

```php
<?php

function readLines(string $path): Generator
{
    $handle = fopen($path, 'rb');

    if ($handle === false) {
        throw new RuntimeException('Cannot open file');
    }

    try {
        while (($line = fgets($handle)) !== false) {
            yield rtrim($line, "\r\n");
        }
    } finally {
        fclose($handle);
    }
}
```

Плюс: память `O(1)` относительно числа строк. Минус: генератор одноразовый, усложняет отладку и повторный проход.

## Частые ошибки

- Называть сложность `O(1)`, забывая про размер строки, сериализацию или копирование массива.
- Использовать `array_shift` в цикле и случайно получить `O(n^2)`.
- Не отличать средний и худший случай hash table.
- Забывать память рекурсивного стека.
- Сортировать данные, когда достаточно hash set: `O(n log n)` вместо `O(n)`.
- Использовать binary search на неотсортированных или немонотонных данных.
- Не проверять пустой вход, один элемент, дубли, отрицательные числа, `null`.
- В `usort` возвращать `true/false` вместо отрицательного/нулевого/положительного int.
- Модифицировать массив во время `foreach` без понимания поведения.
- Сравнивать строки и числа нестрого, получая неожиданные приведения типов.
- Игнорировать, что SQL `ORDER BY`, индексы и join algorithms тоже имеют сложность.

2. Предложить простое baseline-решение.
3. Назвать его сложность.
4. Оптимизировать через структуру данных или паттерн.
5. Доказать корректность через инвариант.
6. Пройти крайние случаи.
7. Назвать финальную time/memory complexity.

Шаблон:

> Я использую hash set, чтобы помнить уже встреченные значения. На каждом шаге проверяю, видели ли мы complement. Инвариант: перед обработкой `i` set содержит все элементы слева от `i`. Поэтому если пара существует и второй элемент текущий, мы ее найдем. Время `O(n)`, память `O(n)`.

## Senior-level короткие ответы

**Почему `O(n)` может быть хуже `O(n log n)` на практике?**

Из-за констант, cache locality, аллокаций, IO, сетевых вызовов, копирования больших PHP arrays и распределения данных. Big O описывает асимптотику, а не полную latency model.

**Почему PHP array дорогой по памяти?**

Потому что это ordered hash map с buckets, zval и метаданными, а не компактный типизированный contiguous array.

**Когда не стоит оптимизировать алгоритм?**

Когда размер входа мал, bottleneck в БД/сети, код станет существенно сложнее, нет измерений или нет требований по latency/memory.

**Как выбрать между sorting и hash set?**

Hash set обычно дает `O(n)` времени и `O(n)` памяти. Sorting дает `O(n log n)` времени, но может позволить `O(1)` дополнительной памяти и удобные two pointers. Выбор зависит от памяти, необходимости сохранить порядок и доменных ограничений.

**Почему Dijkstra не работает с отрицательными ребрами?**

Он фиксирует минимальную дистанцию жадно. Отрицательное ребро может позже улучшить уже зафиксированную вершину, нарушая инвариант.

**Что важнее для backend-интервью: реализовать quicksort или знать структуры данных?**

Для Senior/Lead важнее уметь выбирать правильную структуру данных, объяснять trade-offs, понимать сложность встроенных операций и видеть, где проблема решается на уровне БД/архитектуры.

## Code review checklist

- Есть ли оценка time и memory complexity для основного пути?
- Нет ли скрытого `O(n^2)` из-за `array_shift`, `in_array` в цикле, nested queries или повторной сортировки?
- Подходит ли структура данных под операции: lookup, insert, delete, min/max, ordered traversal?
- Не копируются ли большие массивы без необходимости?
- Корректно ли обработаны пустой вход, дубли, один элемент, большие числа, `null`, negative values?
- Используется ли strict comparison там, где это важно?
- Comparator для `usort` возвращает int и задает полный порядок?
- Нет ли рекурсии с потенциально большой глубиной?
- Для графа корректно выбрано представление: adjacency list или matrix?
- Для очередей/стеков не используются дорогие операции на начале массива?
- Есть ли измерения, если оптимизация усложняет код?
- Можно ли перенести работу в БД эффективнее: индекс, `ORDER BY`, aggregation, pagination?
